# 테스트 규칙

기준 구현: `stock/api/QualityHoldApiTest.java`

## 기본

- 통합 테스트는 `@ShopIntegrationTest`를 붙인다 (H2 + MockMvc, 테스트마다 롤백, 배치 스케줄 꺼짐).
- 테스트 메서드 이름은 한글로 동작을 쓴다. 예: `품질_담당이_아니면_403()`
- API 테스트는 성공, 입력 오류(400), 권한 없음(403), 대상 없음(404), 상태 충돌(409) 중 해당하는 것을 쓴다. 실패 경로에서는 데이터가 바뀌지 않았는지까지 확인한다.
- 기존 테스트를 고쳐서 통과시키지 않는다. 기대값이 바뀌어야 하면 이유를 보고한다.

## 날짜·시각

- 현재 시각은 `TestClock`으로 정한다: `clock.set(LocalDateTime.of(2026, 11, 1, 0, 0))`. 기본값은 2026-10-12 10:00이고, 테스트가 끝나면 기본값으로 돌아간다.
- 날짜 경계(기한 당일, 다음 날 0시, 월 경계)는 구체적인 날짜로 테스트한다.

## 배치

- 판정 로직은 Service 메서드에 판정 날짜를 넘겨 테스트한다. 예: `xxxService.stopExpired(LocalDate.of(2026, 11, 1))`
- 실행 이력까지 확인할 때는 `TestClock`을 맞추고 `XxxJob.run()`을 호출한다. 성공 여부는 `BatchRunner.findLastStatus(XxxJob.JOB_NAME)`로 확인한다.
- 스케줄 선언(cron, zone)은 리플렉션으로 `@Scheduled` 값을 확인한다.

## 테스트 데이터

- `TestData`로 만든다. 로트 번호는 테스트 전용 접두어(`TL-`)를 써서 `data.sql` 샘플과 겹치지 않게 한다.
- 필요한 헬퍼는 `support/TestData.java`에 추가해도 된다. 기존 헬퍼의 시그니처와 동작은 바꾸지 않는다.
- 합계나 배치 대상처럼 `data.sql` 샘플까지 함께 잡히는 기능은, 데이터를 넣기 전 값과 비교하거나 테스트에서 만든 데이터만 확인한다.

## 알려진 공백 (기존 테스트)

이 규칙보다 먼저 만든 테스트에는 아직 맞추지 못한 곳이 있다. 새로 쓰거나 고치는 테스트부터 규칙을 따르고, 기존 테스트는 그 기능을 고칠 때 함께 보완한다.

- `LotApiTest`: 입고·출고 실패 테스트 일부가 데이터가 그대로인지 확인하지 않는다. 출고 API의 권한 없음·대상 없음 테스트가 없다
- `PartnerStockSyncServiceTest`: 전송 건수를 `data.sql` 샘플까지 포함해 확인한다
- 제휴몰 재고 연동 배치: Job 실행 이력(`run()`), 스케줄 선언, 매핑이 없을 때 전체 롤백을 확인하는 테스트가 없다
