# 스키마·기준 데이터 규칙

`schema.sql`·`data.sql`은 애플리케이션(H2 인메모리, MSSQL 모드)을 시작할 때마다 새로 만든다. 운영 DB에는 자동 반영되지 않는다.
`./gradlew dbReset`은 같은 파일로 개발 DB(`.local/db/dev`)와 운영 흉내 DB(`.local/db/prod`)를 다시 만든다.

## "추가만"의 뜻

| 할 수 있음 | 하지 않음 |
|---|---|
| 기존 테이블에 컬럼 추가, 새 테이블·시퀀스 추가 | 기존 컬럼의 이름·타입·기본값·제약 변경 |
| 새 INSERT 문 추가 | 컬럼·테이블 삭제 |
| 파일 끝에 기존 데이터를 채우는 UPDATE 추가 | 기존 INSERT 문의 값 수정, 기존 행 삭제 |

- 기존 테이블에 컬럼을 붙일 때는 `CREATE TABLE` 안에 넣는다. 그 때문에 앞 줄 끝에 쉼표를 붙이는 것은 수정으로 보지 않는다.
- 공통코드 같은 기준 데이터는 기존 INSERT 문에 행을 끼워 넣지 말고 새 INSERT 문으로 추가한다.

## 운영 반영 보고

바꾼 내용은 완료 보고에 "운영 반영 사항"으로 따로 적는다.

- 컬럼·테이블: 운영 DB에서 실행할 `ALTER TABLE`·`CREATE TABLE` 문
- 기존 데이터 보정: 실행할 UPDATE 문. 새 코드가 값을 채우기 시작한 뒤(배포 뒤)에 실행하고, 이미 값이 있는 행은 건드리지 않게 조건을 둔다 (예: `AND 새컬럼 IS NULL`)
- 기준 데이터(공통코드 등): INSERT 문과 반영 시점 (그 데이터를 읽는 코드가 처음 돌기 전)
- 반영 순서: ① DDL·기준 데이터(배포 전) → ② 애플리케이션 배포 → ③ 기존 데이터 보정(배포 뒤). 배포 전에 추가하는 컬럼은 NULL 허용이거나 기본값이 있어야 기존 코드가 깨지지 않는다
