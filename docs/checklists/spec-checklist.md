# SPEC 점검 체크리스트

정리본(requirements.md)은 `requirements-checklist.md`(기존 spec-checklist.md를 이름만 바꾼 것)로 점검한다.
이 체크리스트는 AI에게 넘기기 직전의 SPEC을 점검한다. 항목마다 통과/미통과와 근거 위치(절, ID)를 적는다.

| 영역 | 확인 항목 |
|---|---|
| 생성 조건 | 정리본 7절 미결이 0건인가 |
| 근거 | SPEC의 규칙·동작이 모두 정리본 3절(R) 또는 탐색 5절(T)에 있는가 / 정리본 4절의 AC가 SPEC 7절에 빠짐없이 있는가 |
| 깔끔함 | 출처·협의 날짜·결정 이력·미결·템플릿 주석이 없는가 / CLAUDE.md·`.claude/rules/`에 있는 공통 규칙을 반복하지 않는가 |
| 범위 | 이관·폐지된 항목이 '구현하지 말 것'에 있는가 / 건드리면 안 되는 파일·메서드·동작이 '수정 금지'에 있는가 |
| 위치 | 5절의 수정 대상 파일이 실제로 있는가 / 신규 파일이 이미 있지 않은가 / 탐색 3절의 숨은 영향(데이터로만 연결된 곳, 예외가 나는 기존 메서드)이 '주의'나 구현 순서에 있는가 |
| 계약 | 새 API·배치·스키마·기준 데이터가 요청·응답·오류·운영 반영까지 적혀 있는가 / 운영 반영이 배포 전·후 순서까지 정해져 있는가 |
| 검증 | AC마다 검증(테스트 파일 또는 명령)이 있는가 / 날짜·수량 경계값이 구체적인 값인가 / E2E 시나리오가 실행 가능한가 |
| 순서 | Task가 끝날 때마다 테스트가 통과하는 순서인가 / 같은 Task·같은 배포로 묶을 것이 적혀 있는가 / 커밋하라는 지시가 없는가 |
