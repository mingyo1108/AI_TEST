# 정리본 점검 체크리스트

확인 항목(`/`로 나뉜 질문 하나하나)마다 통과/미통과로 판정하고, 근거가 된 정리본의 위치(절, 규칙 ID, AC 번호)를 적는다. SPEC은 `spec-checklist.md`로 점검한다.

| 영역 | 확인 항목 |
|---|---|
| 추적성 | 요구사항마다 출처(요구사항 ID + 협의 날짜 또는 최종요구사항 번호)가 있는가 / 원문·협의 이력·최종요구사항에 없는 요구사항이 없는가 (원문에 없어 채운 내용은 가정으로 표시) |
| 최신성 | 협의에서 바뀐 결정은 최신 결정만 요구사항에 있고, 이전 결정은 결정 이력에 있는가 / 다른 요구사항으로 넘어간 내용이 범위 제외에 이관처와 함께 있는가 |
| 검증 가능성 | 수용 기준이 Given/When/Then인가 / 날짜·시각·수량 같은 경계값이 구체적인 값으로 적혀 있는가 (예: 기한 당일, 0시, 기준 수량과 같을 때) |
| 완결성 | 해제·취소·정정처럼 처리를 되돌린 뒤의 동작이 수용 기준에 있는가 / 이미 다른 처리(보류 등)가 걸린 대상과 겹칠 때의 동작이 수용 기준에 있는가 |
| 분리 | 클래스명·테이블명·상태 코드값 같은 구현 방법이 없는가 (기술 결정은 탐색 문서 5절에 쓴다) |
| 미결 | 협의되지 않았거나 다른 부서·문서의 확인이 필요한 내용이 7절 미결에 있고, 누구에게 물을지 적혀 있는가 |
| 도식 | 상태도의 상태와 전이가 요구사항·수용 기준과 일치하는가 (되돌린 뒤·겹칠 때의 전이 포함) |
