# 업무 안내 (한 장 요약)

식품 온라인몰의 재고 백오피스가 다루는 업무를 정리한다. 상품 등록·주문·결제는 다른 시스템이 맡는다.

## 용어

| 용어 | 뜻 |
|---|---|
| 상품 | 몰에서 파는 품목. 신선·냉동·가공식품과 생활용품. 기본정보(상품명·분류·판매가)는 상품 관리 시스템에서 등록하고, 상품 관리 시스템 쪽 연동 작업이 이 시스템의 `product` 테이블에 넣어 준다(이 시스템에는 받아 오는 코드가 없다). 다시 넣을 때는 기본정보만 갱신된다. 재고 운영에 필요한 상품별 설정은 이 시스템이 관리한다 |
| 입고 로트 | 같은 상품이라도 입고할 때마다 로트를 새로 만든다. 재고는 로트 단위로 관리한다 (로트 번호 `LT-yyMMdd-0001` 형식. 뒤 4자리는 날짜와 상관없이 이어지는 일련번호) |
| 소비기한 | 포장에 표시된 날짜. 입고할 때 로트에 기록한다. 생활용품처럼 소비기한이 없는 상품도 있다 |
| 로트 상태 | AVAILABLE(판매 가능) / HOLD(판매 보류) / SOLD_OUT(소진) |
| 판매 보류 | 팔면 안 되는 로트를 막는 것. 사유별로 한 건씩 기록하고 사유별로 해제한다. 활성 보류가 하나라도 있으면 HOLD |
| 품질 보류 | 사유가 품질 이슈(이물 신고, 고객 클레임 등)인 판매 보류. 품질 담당이 등록·해제한다. 소진 로트에도 품질 이력으로 기록할 수 있다(팔 재고가 없으므로 상태는 소진 그대로) |
| 출고 | 주문 상품을 로트에서 내보내는 것. 판매 보류·소진 로트는 출고할 수 없다 |
| 판매 가능 재고 | 판매 가능(AVAILABLE) 로트의 수량 합계. 판매 보류 로트는 빠진다 |
| 제휴몰 | 외부 오픈마켓(오늘장터, 싱싱마켓). 우리 재고를 제휴몰에 연동해 판다 |
| 공통코드 | 코드값과 매핑을 담는 테이블. 개발 DB에는 `data.sql`로 들어가고, 운영 DB는 따로 반영을 요청한다 |

## 역할

| 역할 | 하는 일 |
|---|---|
| MD (상품 담당) | 상품별 판매 정책 |
| WAREHOUSE (물류 담당) | 입고, 출고 |
| QC (품질 담당) | 품질 보류 등록·해제 |

## 처리 흐름

1. **입고 → 판매 → 출고**: 물류 담당이 소비기한과 함께 입고하면 로트가 판매 가능 상태로 생긴다. 판매 가능 로트만 판매 가능 재고에 잡히고 출고할 수 있다. 다 나가면 소진.
2. **판매 보류**: 문제가 생긴 로트는 사유와 함께 판매 보류를 건다. 보류 중에는 판매 가능 재고에서 빠지고 출고할 수 없다. 사유가 해소되면 그 사유의 보류만 해제하고, 다른 사유의 보류가 남아 있으면 계속 판매 보류다.
3. **제휴몰 재고 연동**: 30분마다 제휴몰 재고 연동 배치가 로트별 재고와 상태를 제휴몰로 보낸다.
